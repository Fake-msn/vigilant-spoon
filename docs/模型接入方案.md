# 模型接入方案

> 版本：v1.0 · 2026-08-07
> 目标：盘点当前项目所有模型参与组件的接入现状，统一配置项，为后续接入 LLM / 文生图提供落地路径。

---

## 1. 现状结论

当前项目中**唯一真正调用在线模型的是语音对话服务**（F2，DashScope realtime，OpenAI-realtime 兼容协议）。

书信生成、班宠画像生成**均未调用任何在线模型**：

- **书信**（`server/app/services/letter.py`）：纯模板填槽，`generate_letter` 仅拼接字符串，`source="template"`。
- **班宠画像**（`server/app/routers/growth.py::create_portrait`）：**纯占位实现**。接口直接向 `jobs` 表写入一条 `status="done"` 的 job，`result_url` 指向 `/static/portraits/{student_id}.png`，但全仓**没有任何代码生成该 png、没有 static 目录、没有静态文件挂载**——前端获取该 URL 实际会 404。

## 3. 模型类型归并

| 模型类型 | 涉及组件 | 当前接入状态 |
|---------|---------|------------|
| **对话 / Realtime**（语音） | 语音对话 | ✅ 已接入 DashScope（OpenAI-realtime 兼容） |
| **文本生成 LLM**（书信 / 备课 / 评分） | 书信、备课、评分 | ❌ 全部模板 / 确定性 |
| **文生图**（班宠画像） | 班宠画像 | ❌ 完全未接入（连伪实现也没有） |

> 说明：RAG（检索增强）的任务清单条目（`app/services/rag.py`）实际不存在，且按"RAG 铁律"仅用于开场素材 / 备课 / 评语，对话轮次内不调用 RAG 工具。

## 4. 配置现状与统一方案

### 4.1 现状

`server/app/config.py` 仅有语音相关 4 项配置：

```python
voice_provider: str = "local"            # local | dashscope
dashscope_api_key: str | None = None
dashscope_realtime_url: str = "wss://dashscope.aliyuncs.com/api-ws/v1/realtime"
voice_model: str = "qwen3.5-omni-flash-realtime"
```

### 4.2 统一配置建议

按**能力维度**拆分配置，并为每个能力保留"确定性/占位 fallback"，保证未配置 key 时系统仍可稳定演示：

```python
class Settings(BaseSettings):
    database_path: str = ...

    # ---- 1. 语音 realtime ----
    voice_provider: str = "local"              # local | dashscope
    voice_model: str = "qwen3.5-omni-flash-realtime"
    voice_realtime_url: str = "wss://dashscope.aliyuncs.com/api-ws/v1/realtime"
    voice_api_key: str | None = None

    # ---- 2. 文本生成 LLM（书信 / 备课 / 评分，当前未接入）----
    text_provider: str = "template"            # template | dashscope | openai
    text_model: str = "qwen-plus"
    text_base_url: str = "https://dashscope.aliyuncs.com/compatible-mode/v1"
    text_api_key: str | None = None

    # ---- 3. 文生图（班宠画像，当前占位）----
    image_provider: str = "placeholder"        # placeholder | dashscope
    image_model: str = "wanx2.1-t2i-turbo"
    image_base_url: str = "https://dashscope.aliyuncs.com/api/v1/services/aigc/text2image"
    image_api_key: str | None = None
```

### 4.3 配置项对照表

| 能力 | 配置项 | 可选值 | fallback |
|-----|--------|--------|----------|
| 语音 realtime | `voice_provider` / `voice_model` / `voice_realtime_url` / `voice_api_key` | `local`、`dashscope` | `local` 脚本回放 |
| 文本 LLM | `text_provider` / `text_model` / `text_base_url` / `text_api_key` | `template`、`dashscope`、`openai` | `template`（现有模板） |
| 文生图 | `image_provider` / `image_model` / `image_base_url` / `image_api_key` | `placeholder`、`dashscope` | `placeholder`（生成占位图） |

## 5. 分级落地路径

按风险 / 价值排序，逐级推进：

### 5.1 文本能力接入 LLM（书信 / 备课 / 评分）

- 新增 `server/app/services/llm.py`，统一封装 `chat_completion`（`text_provider=dashscope` 走 OpenAI 兼容协议，`openai` 走原生 SDK）。
- `text_provider=template` 时回退到现有模板实现（`letter.py` / `lesson.py` / `scoring.py`），保证零风险兼容。
- 评分尤其适合 LLM（任务清单 F3-01 本就规划"LLM 吃转写全文 → ScoreCard + evidence"）。

### 5.2 补全班宠画像真实生成

- 新增 `server/app/services/imagegen.py`，走 DashScope 文生图接口。
- `image_provider=placeholder` 时生成占位图并落盘，避免 404。
- 需在 `app/main.py` 挂载 `/static` 静态目录。

### 5.3 配置界面（可选，与"教师端配置页问题"衔接）

| 方案 | 教师端体现 | 说明 |
|-----|----------|------|
| B. 只读状态卡 | 控制台新增一页，展示当前 provider / model / 是否已配 key | 轻量，API key 不展示 |
| C. 教师可编辑 | 新增"语音 / 模型服务配置"页，可改 provider / model / url / key | 需新增配置持久化表 + GET/PUT 接口 |
| D. 管理员后台 | 同 C 但仅管理员可见 | 学校统一管控 |

---

## 6. 风险与约束

- **宠物铁律**：宠物三态转移必须是纯函数、零 LLM，任何接入不得触碰 `pet.py`。
- **RAG 铁律**：RAG 不得出现在对话轮次内，仅限开场素材 / 备课 / 评语。
- **演示铁律**：未配置 key 时，所有能力必须能通过 fallback 完整体验，不因缺 key 而阻塞演示。
- **API key 安全**：配置只在服务端读取，前端只读方案不返回 key；可编辑方案需脱敏展示。
